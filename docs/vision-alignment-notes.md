# 視覺對位（Vision Alignment）知識整理

> 本文件是除錯工具的背景說明，也是現場排查時的檢查清單。
> 標示「⚠ 待查證」的內容，請以你手上 Omron FH 手冊的版本為準。

---

## 1. 對位在做什麼

```
拍照 → 找特徵（像素座標）→ 校正轉換（像素 → 平台 mm）
     → 與目標比較 → 求平台修正量 (ΔX, ΔY, Δθ) → 換算各軸指令 → 移動
     → （再拍照確認，未進公差就重複）
```

對位失敗通常不是「計算錯」，而是**某一個座標轉換的假設跟機台實際不符**。除錯的核心就是逐段確認每一次座標轉換。

---

## 2. 座標系

| 座標系 | 單位 | 說明 | 常見錯誤 |
|---|---|---|---|
| 影像座標 (u, v) | px | 原點在影像左上，u 向右、v **向下** | 忘了 v 向下，Y 方向相反 |
| 平台／世界座標 (X, Y) | mm | 對位計算用的共同座標，通常 Y 向上、θ 逆時針為正 | 各相機各自校正，沒有統一到同一個世界座標 |
| 軸座標 | mm / deg / pulse | 各馬達自己的位置 | 軸方向、比例、原點與世界座標不一致 |

本工具的慣例：世界座標 mm、Y 向上、θ 逆時針為正。

## 3. 校正（Calibration）

### 3.1 像素 → 世界的仿射轉換

```
X = A·u + B·v + C
Y = D·u + E·v + F
```

六個參數就能描述：像素當量（mm/px）、相機旋轉角、X/Y 反向、相機在世界座標的位置，以及少量的歪斜。

- **像素當量**：`sx = √(A² + D²)`、`sy = √(B² + E²)`，兩者應接近；差很多代表像素非正方或校正錯誤。
- **手性（行列式 A·E − B·D 的正負）**：一般「由上往下看」的相機，因為影像 v 向下、世界 Y 向上，行列式為**負**；「由下往上看」的相機（例如下視對位相機）影像本身是鏡像，行列式常為**正**。同一組對位中各相機手性不同，若不是上下視混用，幾乎一定是反向設定錯誤。
- **正交性**：u、v 軸在世界座標的夾角應為 90°；偏差大代表校正點取錯或機構不正交。

### 3.2 校正方法

| 方法 | 做法 | 特點 |
|---|---|---|
| 校正板 / 點陣板 | 拍已知間距的圓點或棋盤格 | 可同時修正鏡頭畸變；但板子座標≠平台座標，還需要再對位到平台 |
| **N 點校正（常見 9 點）** | 平台帶著標記移動到 3×3 已知位置，各拍一次 | 直接得到「像素 ↔ 平台移動量」，最常用於對位 |
| 手眼校正 | 相機裝在機構上（隨動）時使用 | 需要考慮相機自己的移動 |

N 點校正的檢查重點：
1. 每一點的**殘差**（擬合後的誤差）都應小於幾個像素以內，突然一點特別大 → 該點找錯特徵或平台沒到位。
2. 校正移動範圍要涵蓋實際對位會用到的範圍。
3. 校正時與生產時的**工作距離 / 對焦**要相同，否則像素當量會變。

### 3.3 旋轉中心

旋轉中心錯誤是**最常見的不收斂原因**：位置算對了，一轉角度就跑掉。

求法：平台只轉 θ（例如 −2°、0°、+2° 或更多點），拍同一個標記，用這些點擬合圓，圓心即旋轉中心（在世界座標中）。

- 旋轉角度太小 → 圓弧太短，圓心誤差大。
- XYθ 平台（θ 在 XY 之上）：旋轉中心會隨 XY 移動，計算時要用「拍照當下」的位置。
- 症狀：只有平移時對得準，有角度時每次都差一點、反覆修正才進公差；且誤差大小與角度修正量成正比。

## 4. 相機配置

| 相機數 | 可求得 | 典型用途 | 注意 |
|---|---|---|---|
| 1 台 | X、Y，θ 需靠特徵本身的角度 | 小工件，整個工件在一個視野內 | 角度精度受特徵大小限制 |
| 2 台 | X、Y、θ（兩標記連線） | 最常見：基板 / 面板兩端標記 | 兩標記距離越遠，角度越準 |
| 3–4 台 | X、Y、θ ＋ 擬合殘差 | 大型面板四角、需要驗證伸縮 | 多點才能看出「無法同時對準」 |
| 上下視 | 物件對物件（貼合） | 上相機看 A、下相機看 B | 兩組相機需校正到同一世界座標 |

本工具的相機數量可任意增減（1–16 台），每台各自設定光學與校正；「拍照點」另外設定，所以一台相機可以拍多個 mark。

### 4.1 粗／精兩段對位（大視野＋高倍率）

高倍率相機（例如 3 倍遠心，視野約 2.8 mm）精度高但視野小，工件上料誤差（數 mm）會讓 mark 不在視野內，因此先用低倍率大視野相機粗對位，再用高倍率相機精對位。

- 粗對位公差只需讓 mark 落在精對位視野內並留餘裕，不必設太嚴；一般鏡頭（非遠心）的倍率會隨 Z 改變，公差太嚴反而因 Z 變化造成永遠不過。
- 精對位相機若靠線馬移動到各 mark，**線馬的定位誤差會直接變成量測誤差**，應使用光學尺回授的實際位置。
- 精對位建議「至少修正 1 次」，避免停在公差邊緣。
- 用精對位相機做旋轉中心校正時，視野太小轉不了大角度，需用線馬跟著 mark 走，或改用粗對位相機。

詳細數據見 [simulation-report.md](simulation-report.md)。

## 5. 對位模式與計算

### 5.1 對位模式

- **對登錄位置（絕對）**：事先登錄「標準品在正確位置時」的像素座標當目標，之後每次讓工件回到這些位置。本工具的「目前→目標」按鈕即為此用途。
- **物件對物件（相對）**：目標由另一組量測決定（例如遮罩標記），兩者都在變動。
- **貼合**：類似相對對位，但通常還要加上偏移量（offset）。

### 5.2 修正量計算

將「目前標記位置 P」與「目標位置 Q」轉到世界座標後，求平台剛體運動：

```
Q ≈ R(θ)·(P − c) + c + T        c：旋轉中心
```

- **最小平方法**：使所有點誤差平方和最小（本工具 v0.1 採用）。
- **最大誤差最小化**：讓最差的那一點盡量小，適合「每一點都要進公差」的場合（Omron 的對位功能也提供這兩種選擇）。本工具「擬合方法」可切換。

### 5.3 擬合殘差與伸縮

剛體只有 3 個自由度（X, Y, θ）。2 台以上相機時：

- **標記間距比 ≠ 1**：目前兩標記距離與目標距離不同 → 工件熱脹冷縮、校正像素當量錯誤、或抓到錯的特徵。
- **擬合殘差 > 公差**：就算平台照著算出的量走，也不可能所有標記同時進公差。這時要決定「誤差平均分配」或「以某一點為主」，而不是一直重複對位。

### 5.4 修正比例（Gain）與迭代

- 實務常用 Gain < 100%（例如 80–90%）避免過衝，再以 2–3 次迭代收斂。
- 若每次修正後誤差方向相反且大小差不多 → 過衝 / 方向反或 Gain 過大。
- 若誤差同方向、每次縮小一定比例 → 比例（像素當量 / 導程 / 齒輪比）錯誤。
- 若誤差在某個值附近跳動不再縮小 → 已到達量測雜訊 / 機構背隙的極限。

## 6. 平台種類

| 平台 | 軸 | 結構 | 運動學（小角度下） |
|---|---|---|---|
| **XYθ** | X, Y, θ | θ 疊在 XY 上，旋轉中心隨 XY 移動 | X = ΔX, Y = ΔY, θ = Δθ（旋轉中心需隨位置更新） |
| **θXY** | θ, X, Y | XY 疊在 θ 上，旋轉中心固定 | XY 方向隨 θ 轉動：`[X, Y] = R(−Δθ)·[ΔX, ΔY]` |
| **XXY** | X1, X2, Y | 兩支 X 向致動器差動產生旋轉，一層完成 XYθ | 各軸 = 該致動點的位移在軸方向的分量 |
| **XYY** | X, Y1, Y2 | 兩支 Y 向致動器 | 同上 |
| **UVW（三軸）** | U, V, W | 三支致動器在平台角落，經交叉滾柱／浮動機構連接 | 同上，致動點位置依機構圖 |
| **UVW（四軸）** | X1, X2, Y1, Y2 | 四角各一 | 同上；四軸冗餘，需同步 |
| 機械手臂 | 依手臂 | 由手臂控制器做逆運動學 | 通常只送 ΔX, ΔY, Δθ 給手臂 |

本工具用**通用致動點模型**計算直線軸：

```
致動點 a（相對旋轉中心）移動後位置 = R(Δθ)·a + T
軸指令 = 軸方向單位向量 · (R(Δθ)·a − a + T)
```

因此 XXY / XYY / UVW / 自訂機構都能用同一公式，只要填對**致動點位置與軸方向**。這也表示 UVW 類平台的關鍵除錯參數是致動點座標（L 值）與方向，填錯就會在有角度時出現誤差。

> 嚴格來說 UVW / XXY 致動器頂端有滑塊與旋轉副，大角度時並非完全線性；一般對位修正角度很小（< 1°）時此模型誤差可忽略。

## 7. 現場除錯檢查清單

依「最常發生 → 較少見」排列：

1. **方向／符號**：單獨給 +X 小量，看影像上標記是否往預期方向移；θ 同樣測一次（逆時針為正？）。
2. **單位**：mm vs μm、deg vs rad、pulse 換算。
3. **旋轉中心**：見 3.3。純平移準、帶角度不準 → 先查這個。
4. **校正與實際不符**：換鏡頭、改工作距離、相機被碰過、重新對焦後沒重新校正。
5. **XY 對調**：相機轉了 90° 安裝，但校正沒跟著改。
6. **觸發時機**：平台還在震動就拍照（需要整定時間）。
7. **特徵搜尋不穩**：光源、反光、模型不唯一；看相關度分數與重複量測的分散。
8. **機構**：背隙、反向間隙、致動器零點不同步（UVW 四軸）。
9. **溫度漂移**：開機一段時間後位置慢慢偏移。
10. **通訊與資料格式**：小數位數被截斷、正負號、欄位順序錯誤。

模擬工具可重現的狀況：在「模擬迭代」中加入量測雜訊、機構比例誤差、旋轉中心偏差，比對現場的收斂曲線，推測問題來源。

## 8. Omron FH 系列相關

### 8.1 相關處理項目（⚠ 待查證：名稱與可用性依軟體版本而不同）

FH 的對位相關功能分為「校正」與「位置計算 / 軸移動量計算」兩大類，常見處理項目方向包括：

- 相機校正（Camera Calibration）、校正資料參照：產生 / 共用像素 ↔ 實際座標的校正參數。
- 平台資料（Stage Data）、機器人資料：設定平台種類（XYθ、UVW 等）與軸參數。
- PLC 主導校正（PLC Master Calibration）、視覺主導校正：由 PLC 或 FH 主導進行 N 點校正與旋轉中心求取。
- 座標轉換、位置資料計算：將多點（Omron 對位相關資料中描述最多 4 點）轉為平台座標，計算對位用的位置與角度，並可選擇**最小平方法**或**最大誤差最小化**。
- 軸移動量計算（單點 / 多點）：直接輸出各軸移動量。

建議查閱：
- *FH/FHV Series Vision System — Processing Item Function Reference Manual*（Cat. No. **Z341**）
- *FH Series Macro Customize Functions Programming Manual*（Cat. No. **Z367**）
- Sysmac 對位控制函式庫（NJ/NX 控制器端的對位計算）

### 8.2 與本工具的對應

| FH 端 | 本工具 |
|---|---|
| 校正參數（像素 → 實際座標） | 相機「仿射矩陣 A–F」模式；或用簡易模式輸入像素當量、角度、中心 |
| 搜尋結果座標 / 角度 | 相機「目前量測 u, v, 角度」 |
| 登錄的基準位置 | 相機「目標 u, v, 角度」 |
| 平台資料 | 平台種類＋軸設定（致動點、方向、反相） |
| 軸移動量輸出 | 「軸指令」表，可與 FH 的輸出值逐一比對 |

**建議的比對流程**：把 FH 的校正參數、量測值、平台設定輸入本工具 → 比較本工具算出的軸指令與 FH 輸出 → 若不同，代表兩邊某個參數的認知不同（方向、旋轉中心、致動點…），從差異的型態判斷是哪一個。

### 8.3 通訊（後續階段）

FH 常用輸出方式：無協定 TCP/UDP、EtherNet/IP、PLC Link、並列 I/O。瀏覽器無法直接開 TCP socket，第 3 階段規劃以小型本機橋接程式（WebSocket ↔ TCP）接收 FH 輸出字串或記錄檔。
